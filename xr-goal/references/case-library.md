# 内联案例库

## 典型案例

### 案例 1：正常分解——「怎样积累高收入技能」

用户说：「我想有一项能让我自由赚钱的技能，不靠工资。」

- 触发条件：目标真实、领域明确，直接从目标倒推必要条件。
- 处理方式：
  - 识别合法、非暴富假设。
  - 从目标倒推四个必要条件：选方向→进入真实交易→资产化→防贬值。
  - 瓶颈分支「进入真实交易」深挖到 4 层，辅助分支只到 1-2 层。
  - 优先级路径按依赖排列：先选方向，再找客户，再做案例，再产品化。
- 判断要点：真实目标不需要均匀的树。瓶颈在哪就往哪深挖，其余分支早停。

**完整输出示例：**

**最终目标**

拥有一项让市场持续付高价的技能，不依赖单一雇主。

**前提假设**

合法路径；技能积累需要时间，不做短期暴富假设。

**条件树**

```text
积累高收入技能
├─ 选对技能方向
│  ├─ 三个条件：有人付钱、不易替代、能做样品
│  └─ 交叉领域溢价更高
├─ 进入真实交易 ⚠️ 最大瓶颈
│  ├─ 学到能卖的最低水平就立刻卖
│  ├─ 接受前几次交付可能不合格
│  ├─ 定价策略
│  │  ├─ 第一个客户可以很低甚至免费
│  │  └─ 目的是换可展示的案例和推荐
│  └─ 客户反馈比课程更精准
├─ 把技能变成可脱离时间的资产
│  └─ 一对一服务 → 一对多产品
└─ 防贬值
   └─ 单一客户收入不超过50%
```

**优先级路径**

1. 列出 3 个有基础且市场付钱的方向，选交叉领域
2. 找到第一个付费客户（可低价），进入真实交易
3. 交付 3-5 个案例后从反馈中迭代并提价
4. 一年后思考如何把服务变成产品

**验证标准**

- 有人未经过推销主动来找你付费
- 时薪在上升而非被压低
- 请假一个月，至少部分收入不中断

### 案例 2：目标太模糊——「我想变得更自律」

用户说：「我想变得更自律，有什么方法？」

- 触发条件：目标太模糊，无法分解。触发「失败模式与兜底」第一行。
- 一线处理：问一个精确澄清问题——「自律对你来说具体指什么？比如你最近一次觉得自己不自律是什么场景？」
- 用户答：「每天晚上刷手机到两点，第二天起不来。」
- 重新定义目标：「晚上 12 点前放下手机睡觉」——一个可观察、可验证的条件。
- 条件树不再用完整的条件倒推框架，而是直接拆「12 点前睡觉」的执行条件：

```text
12 点前睡觉
├─ 11:30 闹钟提醒
├─ 手机充电器移到卧室外面
├─ 床头放一本书替代手机
└─ 第一周允许 12:30 睡，每周提前 10 分钟
```

- 判断要点：模糊目标不要直接拆——先帮用户把目标翻译成一个可观察的行为。翻译完了，树自然就出来了。

### 案例 3：目标太小——「怎么写贪吃蛇」

用户说：「用 Python 写一个贪吃蛇游戏。」

- 触发条件：简单操作问题，不需要复杂的条件倒推。
- 处理方式：
  - 最终目标：一个能在终端里用方向键控制的贪吃蛇。
  - 前提假设：用户有基础 Python 环境；不需要图形界面。
  - 条件树直接用执行步骤：

```text
写贪吃蛇
├─ 搭建游戏循环
│  ├─ 选库：curses（终端）或 pygame（图形）
│  └─ 设计主循环：输入→更新→渲染
├─ 实现蛇
│  ├─ 蛇身用 deque 存储坐标
│  └─ 方向键控制转向
├─ 实现食物
│  └─ 随机生成坐标，吃到后加分并变长
└─ 碰撞检测
   ├─ 撞墙死
   └─ 撞自己死
```

- 判断要点：操作类目标到执行层即可，不需要条件倒推。拆到「用户看一眼就知道从哪开始敲代码」就停。

## 反面案例

### 反面 1：把虚假概念当真实目标拆

用户说：「我想做一个有影响力的个人 IP。」

- 错误做法：直接按目标倒推条件分解——选平台、做内容、积累粉丝、变现。拆出一棵漂亮的树，但根是假的。
- 问题：用户说的「个人 IP」可能是一个虚假概念——他在用这个说法回避「我还没想清楚怎么赚钱」。
- 正确做法：不直接拆。反问：「你说的个人 IP，最终指向什么？你希望它带来钱、合作机会、还是社会认同？」——如果用户说不清，这不是一个可以被分解的目标。先送 `/xrsurvive-game` 做五道测试。
- 诊断要点：**条件树不负责判断目标真假。** 一个假目标拆得越细，用户陷得越深。
